# 新品造型

用户要买衣服、看新品或入手时使用。纯从衣橱搭一套（不买新）时不使用本技能。有风格技能时，轮廓、配色和能不能加外套以风格技能为准，本技能只补共同的造型判断与「新品占哪一槽」。

## 新品占位（默认 vs 整套灵感）

- **默认（点名品类入手，如「推荐两件外套」「想买一条裙子」）**：点名品类是主角，该槽用 `new_item`；**其余槽位必须优先衣橱 XML**，用来证明能搭现有单品。禁止整套全 `new_item`。
- **例外（整套新品造型）**：仅当用户原话或 special_requests **明确**要「整套新品造型」「看新品搭配灵感」「整套都按新品搭」时，才整套都用 `new_item`，不要从衣橱选。
- 用户点名买冬季外套时，外套主角是大衣、棉服或羽绒服（有风格技能时品类按技能）。多套差异主要落在不同新品主角（如两件不同外套），结构仍须不同。

## 先定主角
- 一套只有一个主角。主角是用户点名的那一类；没点名时，是这套里量感最大或颜色最深的一件。
- 其余单品为它服务：颜色更安静，轮廓更简单，不和主角抢领口、袖型和装饰。
- 用户点名外套时，外套就是主角，内搭和下装收着。
- 用户点名的是一整套品类（汉服、连衣裙、套装）时，这套自己就是主角。不要再叠斗篷、大衣、棉服、羽绒服。保暖写在该品类自己的面料和里衬上。

## 配色
- 先定明度，再定色相。整套里要有一块压住的深色，或一组明确对比。禁止每件都是相近的浅色。
- 一套里重复一个元素即可：同一色相、同一金属，或同一圆角。不要领、袖、裙摆、鞋、包各自装饰一遍。
- 肤色只用来决定主角偏暖还是偏冷。没有肤色分析时，不要编造肤色理由。

## 轮廓
- 一套只做一种对比：松对紧，或长对短。不要上装、外套、裙子同时宽松。
- 腰线、肩线、下摆至少有一处是清楚的。三层都盖住腰时，这套没有结构。
- 长度要能读出来：短到哪、长到哪写进外观。不要用「适中」「刚刚好」。

## 两套方案
- 两套必须是两种结构。可以是裤和裙、短外套和长外套、上紧下松和上松下紧。
- 禁止同一件短上衣配长下装，只换一个颜色再出一套。
- 两套的主角不要是同一品类加同一配色公式。

## 检索
- 有天气穿衣细则时，厚度跟细则，本技能不改温度档。
- 用户点名买冬季外套时，外套 query 用厚外套、大衣、棉服、羽绒服。
- 有风格技能时，品类按风格技能，不要改成厚外套。
- 默认模式下：主角槽检索可按新品目标写；其余槽 search_query 面向衣橱召回，禁止假设其余槽也全是新品。
- 用户明确要买/入手某槽新品时，该槽作为新品主角，不再检索衣橱里已有的同槽单品；把搜索留给互补槽。
- 通勤长裤如果需要加绒：描述外侧的通勤结构（如平整斜纹面、清楚腰头/门襟、直筒裤线与裤脚止点）以及内侧薄绒；同时写明无束脚、无抽绳、无罗纹裤口，避免被画成运动保暖裤。其他裤型按其真实风格描述，不套这条细则。
- 多件同槽新品需要成套展示时，除款式结构有别，也让主色方向有可辨差异；尊重用户明确色彩要求，避免默认全部落在灰白中性色。

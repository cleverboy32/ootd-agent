## 2. 软件概述

### 2.1 软件定位

OOTD智能穿搭助手软件是一款基于多智能体（Multi-Agent）架构的人工智能穿搭助手。用户管理自己的数字衣橱与个人形象画像后，可通过自然语言描述场合、天气或单品需求；系统结合衣橱检索结果生成穿搭方案、建议文案与上身效果图，帮助用户减少「今天穿什么」的决策成本。

### 2.2 设计目标

1. **对话即用**：用户以聊天方式提出穿搭问题，系统返回可读方案与可视化效果图。  
2. **基于自有衣橱**：推荐优先使用用户已上传的真实单品，而非脱离衣橱的空泛建议。  
3. **多智能体分工**：意图理解、检索、方案、文案、视觉生成各司其职，便于质量控制和迭代。  
4. **可观测与可回归**：关键环节具备审计日志与测试手段，保障输出质量可持续改进。  
5. **Web 优先、可扩展**：以 Web 应用形态交付，服务端 API 可复用于后续小程序等客户端。

### 2.3 主要功能一览


| 序号 | 功能模块 | 功能摘要 |
|---|---|---|
| 1 | 账户与会话 | 注册、登录、登出、会话保持、安全设置 |
| 2 | 个人画像 | 体型、风格、偏好、地点等画像信息维护 |
| 3 | 数字衣橱 | 单品上传、列表查看、编辑与删除 |
| 4 | 对话穿搭 | 自然语言咨询、意图路由、衣橱检索、方案生成 |
| 5 | 文案输出 | 穿搭建议文案流式展示 |
| 6 | 效果图 | AI 上身效果图生成与质量审核 |
| 7 | 对话历史 | 会话列表、历史消息浏览与续聊 |
| 8 | 访问控制 | 邀请码 / 白名单类访问校验（内测场景） |


### 2.4 软件特点

- **多 Agent 流水线**：Gatekeeper → RAG → Stylist → Copywriter / VisualDirector。  
- **检索与规则结合**：向量相似度检索叠加颜色、季节等过滤逻辑。  
- **流式交互体验**：文案可边生成边展示，降低等待感。  
- **效果图质量门控**：生成后经审核逻辑，降低明显错误出图概率。  
- **全链路审计**：意图、检索、视觉等关键步骤可落盘日志，便于排查与统计。

### 2.5 版本说明

本说明书对应软件版本 **V1.0**。该版本已完成核心对话穿搭链路开发，并以 Web 形式部署用于邀请制内测演示。托管式「穿搭计划」（定时推送每日穿搭）为后续迭代方向，不在 V1.0 必选功能范围内，但其设计复用同一套多智能体管线。

## 5. 功能说明

### 5.1 账户与安全

#### 5.1.1 注册

用户在注册页填写必要账号信息完成注册。系统创建用户记录并建立初始会话能力。若部署开启邀请制，未授权用户可能无法进入完整功能。

#### 5.1.2 登录与登出

用户输入凭证登录后，系统建立服务端会话（Cookie / Session），后续请求在鉴权通过后访问个人数据。用户可主动登出，使会话失效。

#### 5.1.3 安全设置

设置模块支持修改密码、安全问题、恢复码等（以实际页面为准），用于降低账号丢失风险。

### 5.2 个人画像（Profile）

个人画像用于提升穿搭方案的贴合度，典型字段包括：

- 性别 / 体型相关描述  
- 风格偏好（如简约、通勤、度假等）  
- 常驻城市或位置（用于天气相关穿搭）  
- 其他可视化分析所得的辅助标签  

用户可在画像页面查看与更新信息。部分场景下，对话中的资料补充也可触发画像更新流程。

### 5.3 数字衣橱（Wardrobe）

#### 5.3.1 上传单品

用户上传服装图片，系统保存单品记录，并可进行视觉/文本分析，形成便于检索的描述与向量索引。

#### 5.3.2 浏览与管理

衣橱页展示已有单品列表，支持查看详情、编辑元数据、删除单品等操作。衣橱数据是 RAG 检索的基础，单品越完整，推荐越贴合真实可穿范围。

#### 5.3.3 检索侧能力（用户无感）

后台对衣橱条目建立向量索引，并在查询时结合颜色、季节等规则过滤，提高「要白裙子」「夏天穿什么」等请求的命中质量。

### 5.4 对话穿搭（核心）

#### 5.4.1 发起对话

在主界面输入框输入自然语言，例如：

- 「明天去青城山爬山穿什么」  
- 「有没有白裙子，怎么搭」  
- 「这条外套配什么裤子」  

可附带图片（若界面支持）作为当前单品上下文。

#### 5.4.2 意图理解与路由

Gatekeeper 智能体分析用户消息，判断请求类型（如穿搭生成、衣橱浏览、澄清追问、画像更新等），并提取场合、天气、单品锚点、风格等要素。信息不足时可能返回澄清问题，避免盲目生成。

#### 5.4.3 衣橱检索

当需要基于衣橱出方案时，RAG 模块根据检索查询语句在用户衣橱中召回候选单品，供后续 Stylist 选用。

#### 5.4.4 方案与文案

Stylist 基于候选单品与用户画像生成穿搭方案；Copywriter 将方案组织为流畅、可读的中文文案，并以流式方式推送到前端。

#### 5.4.5 效果图

VisualDirector 根据方案与人物/单品信息生成上身效果图，并经过审核逻辑；审核未通过时可重试或降级展示（以实际实现为准）。前端在消息流中展示图片与加载状态。

### 5.5 对话历史

左侧栏或会话列表展示历史对话。用户可切换会话、继续追问（如「裙子呢」在上文已讨论白裙的语境下延续），系统结合会话上下文减少重复澄清。

### 5.6 访问控制（内测）

部署方可启用访问码校验、白名单等机制，仅允许受邀用户使用完整 AI 对话能力。该机制便于比赛演示与合规过渡期管控。

## 6. 典型使用流程

### 6.1 新用户首次使用

1. 使用邀请方式进入系统（若启用访问控制）。  
2. 注册并登录。  
3. 完善个人画像（风格、城市等）。  
4. 上传若干常穿单品至数字衣橱（建议至少覆盖上装、下装或连衣裙、鞋靴等基础品类）。  
5. 返回对话页，发起第一次穿搭咨询。  
6. 阅读方案文案，查看效果图；不满意可追问调整（更正式、更休闲、换颜色等）。

### 6.2 日常快速咨询

1. 登录后直接打开最近会话或新建会话。  
2. 输入今日场合与约束（天气、是否走路多、是否有会议等）。  
3. 等待系统返回文案与效果图。  
4. 按方案从真实衣橱取衣穿着。

### 6.3 围绕单品搭配

1. 在衣橱中确认目标单品已上传，或在对话中描述/上传该单品。  
2. 提问「这件怎么搭」「有没有能配它的裙子」。  
3. 系统锚定该单品后检索互补单品并生成整套方案。

### 6.4 演示讲解路径（比赛 / 验收）

建议演示顺序：登录 → 展示衣橱 → 展示画像 → 发送一句完整场景问句 → 展示流式文案 → 展示效果图 → 说明多智能体分工与审计能力。可辅以预先录制的演示视频，避免现场网络波动。

### 6.5 用户操作界面说明（文字示意）

主界面通常包含：

- **侧边栏**：会话列表、入口导航（衣橱、画像、设置）。  
- **顶栏**：当前会话信息、辅助操作。  
- **消息区**：用户消息与助手回复（文案、单品引用、效果图）。  
- **输入区**：文本输入、发送、可选附件上传。  

具体视觉样式以实际部署版本为准。

## 7. 系统架构与核心模块

### 7.1 逻辑架构

软件采用前后端一体的 Web 应用结构：

- **表现层**：Next.js 前端页面与组件（对话、衣橱、画像、登录等）。  
- **接口层**：App Router 下的 API Route（认证、会话、衣橱、生成编排等）。  
- **智能体层**：`server/agents/*` 多智能体实现。  
- **服务层**：大模型调用、向量嵌入、天气、对象存储等。  
- **数据层**：PostgreSQL（用户、会话、衣橱、画像等）及向量检索相关存储。

### 7.2 核心处理链路

一次典型穿搭请求的数据流如下：

1. 前端将用户消息提交至生成接口。  
2. 编排层调用 Gatekeeper，得到结构化意图。  
3. 若需检索衣橱，调用 RAG 得到候选单品列表。  
4. Stylist 生成穿搭方案（选用哪些单品、如何组合）。  
5. Copywriter 流式输出文案；VisualDirector 并行生成效果图。  
6. 结果经接口推送至前端展示，并写入会话消息。

### 7.3 智能体职责


| 模块路径 | 名称 | 职责 |
|---|---|---|
| `server/agents/gatekeeper/` | Gatekeeper | 意图识别、要素抽取、路由与衣橱锚点解析 |
| `server/agents/intent/` | Intent | 意图类型定义、规范化与 finalize 路由决策 |
| `server/agents/rag/` | RAG | 衣橱语义检索与结果组织 |
| `server/agents/stylist/` | Stylist | 穿搭方案生成 |
| `server/agents/copywriter/` | Copywriter | 文案生成 |
| `server/agents/visual/` | VisualDirector | 效果图生成、提示构建、质量审核 |
| `server/agents/user-profile/` | UserProfile | 用户画像相关智能处理 |


### 7.4 支撑模块


| 模块 | 说明 |
|---|---|
| `server/auth/` | 认证、会话、锁定与访问控制 |
| `server/utils/` | 颜色匹配、季节过滤、流式辅助、评估器等工具 |
| `server/logging/` | 各智能体审计日志 |
| `server/services/` | LLM、嵌入、天气、存储等外部服务封装 |
| `server/config/` | 模型与运行配置 |
| `app/api/` | HTTP API 与生成编排（含 LangGraph 相关编排代码） |


### 7.5 质量保障

- **单元测试**：覆盖意图处理、颜色匹配等纯逻辑。  
- **Prompt 回归测试**：对关键对话场景调用真实模型，断言结构化字段。  
- **审计日志**：如 gatekeeper、rag、visual 等 JSONL 日志，用于统计意图分布、检索命中与出图质量。

## 8. 数据与接口概要

### 8.1 主要业务数据

- 用户账号与安全凭证摘要  
- 会话（Conversation）与消息（Message）  
- 衣橱单品（图片引用、描述、嵌入向量元数据等）  
- 用户画像与偏好  
- 访问控制与审计相关记录  

### 8.2 主要 API 类别（示意）


| 类别 | 路径前缀示例 | 说明 |
|---|---|---|
| 认证 | `/api/auth/*` | 注册、登录、登出、改密、会话 |
| 会话 | `/api/conversations*` | 会话 CRUD 与消息 |
| 衣橱 | `/api/wardrobe*` | 单品列表与详情 |
| 上传 | `/api/upload` | 图片上传 |
| 生成 | `/api/generate-with-image` | 穿搭生成主接口 |
| 画像 | `/api/profile/*` | 画像与视觉分析 |
| 访问 | `/api/access/*` | 内测访问校验 |


接口均为服务端鉴权后的业务 API，具体请求体与响应字段以源码类型定义为准。

### 8.3 日志与可观测性

开发与运维可将审计日志输出至 `log/` 目录下的 JSONL 文件（如 gatekeeper-audit、rag-search、visual-audit 等），用于问题定位与质量统计。生产环境应控制日志中的个人敏感信息范围。

## 9. 异常处理与常见问题

### 9.1 常见问题


| 现象 | 可能原因 | 处理建议 |
|---|---|---|
| 无法登录 | 账号密码错误、会话配置错误 | 核对凭证与环境变量中的会话密钥 |
| 对话无响应 | 模型服务不可用、网络受限、配额耗尽 | 检查模型供应商状态与密钥、查看服务端日志 |
| 推荐不贴合衣橱 | 衣橱为空或单品过少、检索查询不佳 | 补充上传单品；查看 rag 检索日志 |
| 效果图失败 | 图像模型超时或审核未通过 | 重试；检查 visual 审计日志 |
| 页面空白 | 前端构建失败或反向代理配置错误 | 检查 `pnpm build` 与网关配置 |


### 9.2 运行期异常原则

1. 接口层捕获可预期错误并返回明确错误信息，避免将内部堆栈直接暴露给终端用户。  
2. 模型调用对限流（如 HTTP 429）实施有限次重试。  
3. 关键生成路径支持中止信号，避免用户取消后仍长时间占满资源。  
4. 审核未通过的效果图不作为「成功成品」直接交付（按产品策略重试或提示）。

### 9.3 数据备份建议

定期备份数据库与重要对象存储桶。升级版本前先在预发环境验证迁移脚本。

### 9.4 卸载

停止 Node 服务进程，删除部署目录与不再需要的数据库实例即可完成卸载。云资源需在对应控制台释放，以免持续计费。
